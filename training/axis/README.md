# UP 视频轴提取

把 B 站攻略视频里的操作提取成机器可执行的轴：**视频回答“该在什么时候做什么”，自己的录像回答“画面现在处于什么状态”**——不需要自己会打这条轴。

## 工作流

```text
① 拿到源视频（本地 mp4，优先 1080p60；30fps 单帧量化约 33ms）
   ↓
② 逐帧标注         py -3.12 training/axis/annotate_video.py --video up.mp4
   只标“动作在画面上出现”的帧 → up.axis_timeline.json
   ↓
③ 编译             py -3.12 training/axis/compile_axis.py --timeline up.axis_timeline.json
   ├─ 视觉事件 → 估计输入时间表
   ├─ RawInputTimeline 宏源码
   └─ 按站场分组的状态机轴节点草表
   ↓
④ 输入延迟校准
   不同动作的“按下 → 画面出现”延迟通常不同；严格切人还可能依赖前一个动作。
   用 --action-lead / --transition-lead 校准，不要只靠一个全局常数。
   ↓
⑤ 对齐验收
   先离线检查编译时间表和告警；实机阶段再录自己的执行画面与 UP 视频逐帧对齐。
```

## 标注器按键

| 键 | 含义 |
| --- | --- |
| `, / .` | 上一帧 / 下一帧 |
| `J / L` | -10 / +10 帧 |
| `P` | 播放 / 暂停 |
| `A` | 普攻（左键） |
| `V` | 下落 A |
| `E / Q / R / F / W` | 对应技能键 |
| `Z` | 重击（长按左键） |
| `I` | 变奏入场（对齐标记，不产生输入） |
| `1 / 2 / 3` | 切人，同时更新“当前站场” |
| `X` | 撤销最后一个事件 |
| `S` | 保存 |
| `Esc` | 保存并退出 |

`Q` 专门用于标技能 Q，不再和退出热键冲突。已有 timeline 再次打开时会自动跳到最后一个已标事件，方便长视频断点续标。

## 视觉时刻与输入时刻

标注文件中的 `ms` 永远表示**视觉出现时刻**。编译器按下面的优先级反推输入：

```text
transition lead > action lead > global lead
```

例如：

```powershell
py -3.12 training/axis/compile_axis.py `
  --timeline up.axis_timeline.json `
  --lead-ms 0 `
  --action-lead "a=45,e=80,r=110,s2=60" `
  --transition-lead "e:s2=95,a:s3=70"
```

含义：

- 一般 `E` 视觉出现前约 80ms 估计已经按了 E；
- 一般切 `2` 用 60ms lead；
- 但如果上一动作是 `E`，`E → 2` 专门使用 95ms，覆盖普通 `s2=60`；
- `a:s3=70` 同理可单独描述某一套极限切人。

这些数字不是固定真值，后续应由本机 telemetry / 对齐实验逐步校准。

### 为什么不再“首事件钳到 0”

RawInputTimeline 是相对宏，不是视频播放器。编译器会先在**原视频时间轴**上估算所有按键时刻，再把最早的一颗输入定义为宏 `t=0`。

因此即使视频前面有 2 秒片头，也不会生成无意义的 2 秒空等；编译报告会写出：

```text
macro_origin_video_ms: ...
```

用它把宏 `t=0` 映射回 UP 视频即可。统一的 global lead 只会整体移动这个原点，不会改变动作之间的相对 gap；真正会改变极限衔接的是不同 action/transition lead 之间的差值。

## 编译选项

- `--lead-ms N`：未单独配置动作时的默认视觉→输入提前量；
- `--action-lead "e=80,r=110,s2=60"`：按动作设置 lead；
- `--transition-lead "e:s2=95,a:s3=70"`：按前一动作→当前动作设置 lead，优先级最高；
- `--hold "z=550,w=180"`：覆盖默认按住时长；
- 编译器会对输入重排、按住截短、同刻输入、视频前摇不足等情况逐条告警。

如果不同 lead 推算出“后出现的画面其实更早按键”，编译器会按**估计输入时刻**排序，同时给出顺序变化告警。极限输入缓冲确实可能出现这种情况，但也可能说明 lead 配得过大，所以必须复查。

## 已知限制

- 当前仍需要人工逐帧标动作；自动识别 UP 视频动作是下一阶段；
- 一次只支持一个按住中的输入，不支持“按住 W 同时按 E”这类和弦；
- 当前状态机节点表保留的是**视频视觉 gap**，估计输入时序单独列在编译报告第 1 部分；
- 带按键显示浮层的视频目前仍靠人工对照浮层标注；
- 视频请自行下载到本地文件；本工具不涉及平台下载与分发。提取出的时序数据如需发布衍生内容，请注明原作者。
